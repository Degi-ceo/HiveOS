# HiveOS UI concept preview — deep audit

Date: 2026-08-22  
Branch: `gpt-ui-improvements`  
Preview: `/?ui-preview=1`  
Release: UI concept v0.8.2

## Result

The fixture-only preview now exposes and validates every one of the 29 approved
mockup states:

- 17 canonical product pages;
- 7 global/detail UI states;
- 5 task/mobile mockup variants.

The audit exercised 29 screen transitions, 70 tab transitions, 111 primary or
row actions, and 93 documented cross-view relationships. No preview interaction
issued a backend request.

Final verification: 107/107 dashboard tests pass across 14 files; the production
Vite build passes. Preview coverage is 100% statements, 100% lines, 100% functions
and 97.24% branches.

## Issues found and fixed

| ID | Severity | Finding | Resolution |
|---|---|---|---|
| UI-A01 | High | Only 24 of 29 approved mockups were reachable | Added Cron, Commitments, Mobile Hub, Mobile Chat and Mobile Navigation states |
| UI-A02 | High | Tabs changed only the highlight | Tabs now update the panel heading, ARIA state and deep-link query |

| UI-A04 | High | Search, notifications and most row actions were inert | Added safe fixture routing and explicit fixture-only feedback |
| UI-A05 | Medium | Task/Cron/Promise tabs did not preserve their correct default tab | Added per-screen default tabs and cross-tab targets |
| UI-A06 | Medium | Overlay concepts had no reliable close path | Added Close and Escape behavior with source-screen restoration |
| UI-A07 | Medium | Mobile rows hid metadata and all row actions | Preserved metadata/actions in the collapsed mobile row layout |
| UI-A08 | Medium | Tablet navigation collapsed to ambiguous dots | Replaced dots with readable two-character route markers and tooltips |
| UI-A09 | Medium | Tabs lacked complete ARIA semantics and keyboard navigation | Added tab/tabpanel links, selected state, roving focus and arrow/Home/End keys |
| UI-A10 | Medium | Related-view paths were visual text only | Converted relationships to safe navigation controls |
| UI-A11 | Low | Every inspector reported “Healthy,” including approvals | Added contextual status labels and warning tones |
| UI-A12 | Low | Fixed `100vh` and unwrapped controls were fragile on mobile | Added dynamic viewport units, wrapped actions, horizontal tab scrolling and safe-area spacing |
| UI-A13 | Medium | Several 9–10 px metadata colors were below 4.5:1 contrast | Raised quiet-text tokens to at least 4.93:1 on their darkest content surface |
| UI-A14 | High | The dashboard coverage configuration excluded `src/ui-preview` | Added preview JS/JSX to V8 coverage with a dedicated 90% threshold |

## Responsive review

- Desktop keeps the 244 px navigation rail and two-surface workspace.
- Below 980 px the inspector stacks below the primary surface.
- Below 820 px the rail becomes a compact but identifiable route strip.
- Below 640 px the full rail is replaced by the five-destination bottom bar;
  the header menu opens the dedicated complete mobile navigation state.
- Mobile rows retain their action and metadata instead of silently removing functionality.
- Dedicated 390 px Mobile Hub, Mobile Chat and Mobile Navigation mockup states are
  available from the preview catalog.

## Safety and scope

- The preview still uses static fixtures only.
- The existing production `Centre` remains the default application.
- No gateway endpoint, token, persisted state, protected file or approval policy was changed.
- Missing backend contracts remain documented in `docs/UI_RELATIONS_AND_API.md`.

cd dashboard
./node_modules/.bin/vitest run

server (`ERR_BLOCKED_BY_CLIENT`). Therefore the repeatable interaction matrix
and build checks are authoritative for this pass; a final screenshot-diff pass
should run in CI or a developer browser before production UI implementation.
