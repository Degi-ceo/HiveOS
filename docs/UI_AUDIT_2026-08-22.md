# HiveOS UI concept preview — deep audit

Date: 2026-08-23
Branch: `gpt-ui-improvements`
Preview: `/?ui-preview=1`
Release: UI concept v0.8.5

## Result

The fixture-only preview now exposes and validates every one of the 29 approved
mockup states:

- 17 canonical product pages;
- 7 global/detail UI states;
- 5 task/mobile mockup variants.

The current contract contains 29 screen states, 70 tabs, 17 primary actions,
82 actionable rows and 93 documented cross-view relationships. The browser
suite must verify the visible destination or state change after every action;
performing a click alone is never a pass condition.

Local verification is 111/111 dashboard tests across 14 files, a successful
production Vite build, and preview coverage of 99.55% statements/lines, 100%
functions and 90.83% branches. The Chromium-only checks are delegated to the
independent `dashboard-preview` GitHub Actions job because this local runner
cannot download a browser binary. They remain pending until the workflow itself
reports success; this document does not convert an unavailable check into PASS.

**v0.8.5 audit correction (2026-08-23):** the v0.8.4 journey and screenshot
scripts could report success without proving user-visible outcomes. The old
screenshot parser also skipped hyphenated IDs, used a machine-specific path,
retained stale output and described 2880×1800 as both viewport and HiDPI output.
Those defects are fixed in v0.8.5.

### Remaining limitations

1. Focus trapping inside overlays remains a production implementation requirement.
2. The artifact is a concept preview backed by fixtures, not a backend-integrated UI.
3. Visual-diff baselines are not yet enforced; the current CI verifies state,
   geometry, errors, isolation and current screenshot generation.
4. User acceptance belongs to the human reviewer. Automated generation or a
   matching screenshot is not recorded as product acceptance.

**v0.8.3 visual audit (2026-08-23):** Complete CSS redesign with premium visual

## Responsive review

- Desktop keeps the 244 px navigation rail and two-surface workspace.
- Below 980 px the inspector stacks below the primary surface.
- Below 820 px the rail becomes a compact but identifiable route strip.
- Below 640 px the full rail is replaced by the five-destination bottom bar;
  the header menu opens the dedicated complete mobile navigation state.
- Mobile rows retain their action and metadata instead of silently removing functionality.
- Dedicated 390 px Mobile Hub, Mobile Chat and Mobile Navigation mockup states are
  available from the preview catalog.

## Safety and scope

- The preview still uses static fixtures only.
- The existing production `Centre` remains the default application.
- No gateway endpoint, token, persisted state, protected file or approval policy was changed.
- Missing backend contracts remain documented in `docs/UI_RELATIONS_AND_API.md`.

## Verification commands

```bash
cd dashboard
npm ci
npx playwright install chromium
npm run verify:preview
```

`verify:preview` runs unit tests, coverage, production build, 29-screen smoke,
real user journeys and screenshot generation. The browser scripts start a
loopback-only server on a dynamic port; no manually managed Vite process is used.
