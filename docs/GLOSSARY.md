# HiveOS — Glossary

Domain-specific terms used throughout the codebase and documentation.
When a term appears in a doc without explanation, this is the canonical definition.

---

## A

**approval gate**
The danger firewall implemented in `Core/approval_gate.py`. Intercepts tool calls whose
arguments match dangerous patterns or whose tool name appears in `DANGEROUS_TOOLS`.
Intercepted calls are queued (not executed) until a human approves or denies them via
`POST /approvals/decide`. The gate file itself is PROTECTED and cannot be modified by Hive.

**approval_id**
A UUID hex string generated by `gate.request()` when a dangerous tool call or REVIEW-tier
self-mod edit is intercepted. Used as the key in `gate._pending` and `HiveOS.edit_pending`.
Sent to the client via `GET /approvals` so they can reference it in `POST /approvals/decide`.

**agents_registry**
A dict on the `HiveOS` dataclass mapping specialist agent names to factory functions.
Populated at build time. Used by `delegate_named(task, agent_name)`. The five built-in
specialists are: `researcher`, `coder`, `reviewer`, `memory-keeper`, `security-reviewer`.

**AUTO tier**
See **RiskTier**.

---

## C

**CommitmentBook**
Persistent store (`autonomy/commitments.py`) of recurring tasks (e.g. "summarise news
every Monday"). Backed by the shared SQLite state DB. The Heartbeat checks commitments
each tick and enqueues them to the TaskBoard when due.

**core (layer)**
The `src/hive/core/` directory. The leaf layer of the architecture DAG — it imports
nothing from any other HiveOS layer. Consequence: cross-layer needs are injected
(callable parameters, not imports). Enforced by a static AST scan in `tests/test_architecture.py`.

**CredentialPool**
`llm/credential_pool.py`. Manages a list of API keys for a single provider. Rotates to
the next key on 429/rate-limit, with per-key cooldown tracking. Keys come from
comma-split env vars (e.g. `MINIMAX_API_KEY=key1,key2,key3`).

**CronScheduler**
`autonomy/cron.py`. Parses cron expressions (requires `croniter` optional extra) and
enqueues tasks to the TaskBoard when they are due. Falls back to interval-only scheduling
if `croniter` is not installed.

**Curator**
`memory/curator.py`. Manages the lifecycle of agent-created skills: active → stale →
archived. Never deletes (soft-archive only). Pinned skills are exempt from lifecycle.
Pre-run backup prevents data loss. Built-in tools registered by `register_builtins` are
marked `agent_created=False` and are therefore Curator-immune.

---

## D

**dangerous tool**
A tool whose `ToolSpec.dangerous` is `True`, or whose name appears in `DANGEROUS_TOOLS`
in `Core/approval_gate.py`. Dangerous tool calls are queued in the approval gate and
never executed automatically. All MCP tools loaded from external servers are marked
dangerous automatically.

**delegate_named**
`agents/delegate.py`. Dispatches a task to a named specialist agent from `agents_registry`.
e.g. `delegate_named("find an MCP server for git", "researcher")`.

**discovery-first**
A hard architectural rule: before building any new capability, search official sources
(Anthropic Skills, MCP Registry, modelcontextprotocol/servers, GitHub). Record the result
in memory. Only build if nothing suitable exists. The `discover` builtin tool implements
the search step.

---

## E

**edit_pending**
A dict on the `HiveOS` dataclass (`approval_id → Edit`). Stores REVIEW-tier `Edit` objects
while they await human approval. In-memory only — survives only for the life of the process.
See [`docs/decisions/005-edit-pending-in-memory.md`](decisions/005-edit-pending-in-memory.md).

**Edit**
`core/spec_search.py`. Dataclass representing a proposed code change: `op: EditOp`,
`summary: str`, `rationale: str`, `apply: ApplyFn`. The `apply` function takes a worktree
path and returns a list of changed file paths.

**EditOp**
`core/spec_search.py`. Enum of valid self-improvement operation types:
- `edit_docs` — documentation update (AUTO tier)
- `add_test` — add a test (AUTO tier)
- `update_config` — configuration change (AUTO tier)
- `patch_code` — code bug fix (REVIEW tier)
- `new_tool` — add a new tool (REVIEW tier)
- `add_capability` — add a new capability (REVIEW tier)
- `refactor` — refactoring (REVIEW tier)
- `manual` — human-only implementation (MANUAL tier)
- `add_agent` — add a new agent (REVIEW tier)

**EditOutcome**
`core/spec_search.py`. Dataclass returned by `SelfImprovement.run()`:
`edit_id`, `op`, `tier`, `status` (applied/pending_approval/manual/failed/blocked_protected),
`detail`, `branch`, `approval_id`.

**EventBus**
`core/events.py`. Thread-safe synchronous pub/sub. Subscribers run in registration order,
isolated from each other's exceptions. **Contract: subscribers must be fast/non-blocking.**
Event types: `INFERENCE_{START,END}`, `TOOL_CALL_{START,END}`, `MEMORY_{STORE,RETRIEVE}`,
`AGENT_{TURN,TICK}_{START,END}`, `APPROVAL_{REQUESTED,RESOLVED}`, `BUDGET_BLOCK`,
`SELFMOD_{START,END}`.

---

## H

**Heartbeat**
`autonomy/heartbeat.py`. The never-idle autonomy loop. Each tick:
1. Fire due cron jobs + commitments onto the TaskBoard
2. If nothing due: plan 1–3 new tasks via the Planner
3. Claim + dispatch pending tasks (bounded by `HIVE_MAX_AGENTS`)
4. Mark done/failed; consolidate memory; curate skills; refresh budget
5. Check for repeated failures and trigger `self_improve_from_symptom` if ≥3 failures

**Hermes**
In the context of HiveOS documentation: the memory runtime — i.e. the Mnemosyne-backed
active memory layer. The name comes from Hermes Agent (Nous Research), the reference
project whose memory/learning design inspired HiveOS's memory architecture.
In CLAUDE.md: "Mnemosyne is the active memory layer; Hermes is the runtime."

**Hive**
The agent. The entity that converses (in Polish), plans, executes, and self-improves.
Hive runs inside HiveOS. Hive is an instance of `ConversationOrchestrator` coordinated
by `HiveOS`. One HiveOS hosts one Hive.

**HiveOS**
The system. The installable `hive` Python package. `HiveOS` is the composition root
dataclass; `HiveOS.build()` wires every subsystem. "HiveOS is the system; Hive is the agent."

**HostLLMBridge**
`llm/host_bridge.py`. Bridges Mnemosyne's synchronous consolidation thread to HiveOS's
async `ModelRouter`. Runs on its own dedicated asyncio event loop in a daemon thread.
Mnemosyne calls a sync `.complete(prompt)` function; the bridge routes it via
`asyncio.run_coroutine_threadsafe` to the real async adapter — no cross-loop client reuse.

---

## L

**LocalMemoryProvider**
`memory/local.py`. Fallback when Mnemosyne is not installed or configured. Uses the shared
SQLite state DB with `episodic` and `knowledge` tables + FTS5 for full-text search.
All APIs are identical to the Mnemosyne provider.

---

## M

**MANUAL tier**
See **RiskTier**.

**MCP (Model Context Protocol)**
A protocol for tool interoperability between AI systems. HiveOS can:
- Act as an **MCP client**: load tools from external MCP servers (`HIVE_MCP_SERVERS`)
- Act as an **MCP server**: expose its own tools to other agents via `hive mcp-serve`

**MemoryKeeper**
`memory/keeper.py`. Runs memory consolidation: reflect → extract → deduplicates → promotes
to long-term. Uses an aux-model summarizer (injected callable — never imports `llm`).

**Mnemosyne**
The active memory layer package (`pip install -e ".[memory]"`). Provides semantic search
(SQLite vec+FTS5), memory banks (BEAM), and `sleep`/`evolve` consolidation. HiveOS wraps
it in `HiveMnemosyneProvider`. When not installed, `LocalMemoryProvider` is used.

**ModelRouter**
`llm/router.py`. Routes completion requests by `TaskKind`:
- `EXECUTE`: executor model chain with failover (MiniMax or Anthropic)
- `AUX`: cheaper auxiliary model (summarization, titling)
- `PLAN`: Codex planner subprocess (thinking-only, never execution)

---

## O

**ObsidianVault**
`memory/vault.py`. Long-term Obsidian-compatible markdown notes. Each note has YAML
frontmatter (`kind`, `title`, `source`, `created`). The vault is the durable linkable
"old memory" — anything important enough to persist across Mnemosyne resets.

---

## P

**PROTECTED**
Files that Hive is categorically unable to modify: `Config/SOUL.md` and
`Core/approval_gate.py`. The self-modifier checks `_touches_protected(changed_paths)` and
returns a `blocked_protected` outcome before any worktree change is attempted. These files
can only be changed by Kamil via a manual merge.

---

## R

**REVIEW tier**
See **RiskTier**.

**RiskTier**
`core/spec_search.py`. Enum that controls the self-modification pathway:
- **AUTO** — change is applied in an isolated worktree, tested, then pushed as a draft PR
- **REVIEW** — change is queued in the approval gate; requires human approval to apply
- **MANUAL** — recorded only; a human must implement the change

The tier is assigned from a **deterministic code table**, not from the model's output.
The model cannot self-escalate (e.g. claim a code change is `edit_docs` to avoid REVIEW).

---

## S

**SelfImprovement**
`core/spec_search.py`. Orchestrates the full self-mod loop: `tiered(edits)` → `_apply_one` per
edit (AUTO → `SelfModifier.propose`; REVIEW → gate.request + pending_store; MANUAL → record).

**SelfModifier**
`core/self_mod.py`. The git-level self-modification engine. `propose(title, description, apply_fn)`
creates a git worktree, calls `apply_fn(worktree_path)`, runs tests, and on success pushes
the branch and opens a draft PR via the GitHub REST API.

**session_id**
A string that identifies a conversation context. Defaults to `"default"`. Each unique
`session_id` has its own message history in the session store. Used by `/chat`,
`/chat/stream`, `/ws`, and the gateway's per-session trace export.

**SkillUsageStore**
`memory/skill_usage.py`. Tracks tool use counts and timestamps in SQLite. The Curator uses
this data to decide which agent-created skills to archive. Built-in tools are registered
as `agent_created=False` and are immune to Curator lifecycle.

**SOUL.md**
`Config/SOUL.md`. The immutable identity and safety contract. Defines Hive's values,
language rules (Polish to Kamil / English in code), hard limits (never auto-merge,
discovery-first, memory rules). Loaded read-only via `src/hive/core/soul.py`.

**spec_search**
The self-improvement subsystem (`core/spec_search.py`). Named after the "spec search"
pattern from OpenJarvis/Voyager — a loop that diagnoses gaps, proposes typed edits, and
applies them through a tiered risk gate.

**SSE (Server-Sent Events)**
The `POST /chat/stream` endpoint uses SSE to stream token deltas to the client as they
are generated. Each delta is one `data:` line. The stream ends with `data: [DONE]`.

---

## T

**TaskBoard**
`autonomy/tasks.py`. Durable SQLite queue. Each task has: `id`, `kind`, `state`
(pending/claimed/done/failed), `payload`, `source`, `attempts`, `last_error`, `created_ts`.
Survives process restart — the Heartbeat picks up pending tasks on the next tick.

**worktree**
A git worktree (`git worktree add -b <branch> <path>`) created by `SelfModifier.propose`
for each AUTO-tier self-mod attempt. The edit is applied and tested in the worktree, never
in the live tree. Cleaned up after the PR is opened (or after failure).
